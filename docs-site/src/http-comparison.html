Latest-release comparison · HTTP upload completion

Controlled uploads complete 8.75% sooner

OpenFrame had lower upload completion latency in all six controlled deployment pairs against Immich v3.3.5. Background workers were excluded equally. The separate default-worker smoke remains inconclusive.

These table values are medians of individual upload requests. The headline instead uses the geometric mean of the six paired deployment-block median ratios. Its exploratory 95% block-bootstrap interval is 6.60–10.66% lower latency.

What ran

Both builds received identical seeded 512 × 512 PNG fixtures, 787,252 bytes each, over loopback HTTP. Requests were sequential. PostgreSQL fsync, full-page writes and synchronous commit stayed enabled; Redis and storage writes were real. Each version used its own disposable database and upload volumes.

The default-worker smoke used three deployment pairs and 15 measured uploads per version. Its candidate median was 4.7% higher. This small, noisy result is inconclusive and remains published. The controlled follow-up used six alternating deployment pairs and 120 measured uploads per version, with one warmup upload per deployment. It set IMMICH_WORKERS_INCLUDE=api equally for both builds, so media processing and geodata jobs did not compete with upload requests. ML was disabled in both experiments.

Versions and correctness

The baseline is official Immich v3.3.5, commit 8303cb117e197c700332b33b61b45314c9cc5bb4. The candidate is the full compiled OpenFrame server source identified by the source and dist hashes in the raw result. It reuses the existing candidate production dependency/native-codec image; web and CLI builds in that image were not refreshed. This is a backend comparison.

All measured deployments passed upload/download byte equality, unauthorized requests returning 401, range requests returning 206, conditional requests returning 304, duplicate upload identity and mixed-encoding preflight checks.

Regression limits

Not a whole-app qualification

The exploratory regression budget was 5%, chosen before the controlled run completed. No regression exceeding that budget was detected in this controlled path. Six paired blocks on one shared host give limited precision. These results do not qualify default-worker throughput, media-ready latency, concurrent capacity, WAN, TLS or mobile clients.

Benchmark commands, assertions, fixture generation and analysis are in the methodology. Analysis resamples whole paired deployment blocks 10,000 times with seed 0, rather than treating individual requests as independent deployments. Disposable containers and volumes were removed after the experiment.
