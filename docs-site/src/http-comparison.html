Lower upload and media-ready latency in this test

Across six paired deployments, the OpenFrame candidate had 16.27% lower HTTP upload completion latency and 15.57% lower thumbnail/preview readiness latency than Immich v3.3.5. These are scoped, exploratory results from one shared host.

The millisecond columns are pooled request medians. Percentage changes use the geometric mean of six paired deployment-median ratios, so they differ from the pooled median ratio. Each build completed 120 measured uploads across six deployments, with order alternating between builds. One pair favored upstream on both metrics. Two upstream deployments were much slower than the others, so host variation affects the estimate.

What ran

Both builds used default API and microservices workers, with only ML disabled. Every deployment started with fresh disposable PostgreSQL and upload volumes. API readiness, geodata import and one complete media warmup finished before measurement. Twenty unique seeded 512 × 512 PNGs followed sequentially per deployment, with identical bytes across builds. PostgreSQL fsync, full-page writes and synchronous commit stayed enabled; Redis and storage writes were real.

HTTP completion includes reading the full upload response. Media-ready time starts before that upload and ends when authenticated thumbnail and preview endpoints both return image content. Unsuccessful readiness polls sleep 50 ms, and polling HTTP cost is included. This is client-observed image readiness, not exact worker execution time or completion of every queue.

Versions and correctness

The baseline is official Immich v3.3.5, commit 8303cb117e197c700332b33b61b45314c9cc5bb4. The candidate is the full compiled OpenFrame server identified by source hash 739ff34582320d749c7ecb7411a098718bbfbc836d30e096bd32c819e7a4e926. It reuses the recorded candidate production dependencies and native codecs; its web and CLI builds were not refreshed. Current backend source and compiled output match the measured hashes.

All twelve deployments passed original byte equality, unauthorized requests returning 401, ranges returning 206, conditional requests returning 304, duplicate identity, ordered mixed-encoding preflight checks and thumbnail/preview readability.

Regression interpretation and limits

Not application-wide qualification

Both intervals lie below the strict zero-slowdown reference, separately from meeting the predeclared exploratory 5% budget. This supports lower latency within this experiment. Shared-host variance and six paired blocks limit confidence. The media-ready interval is only 0.38 percentage points from zero at its near boundary; 50 ms polling further limits interpretation of small differences.

Video, concurrent backlogs, populated libraries, ML, WAN, TLS and mobile clients were not measured. The image reuses recorded dependencies with newly compiled server code; it is not a fresh release image. These results do not prove every workload is faster or regression-free.

Reproduce and inspect

The fixed protocol and handoff with hashes and limitations accompany the harness. Analysis resamples whole paired deployment blocks 10,000 times, seed 0. Disposable containers, volumes and networks were removed.
