Face query

  • The original PersonRepository source is loaded with git show, transpiled with SWC and imported. The patched one comes from the working tree. Both use the same Kysely connection and fixture database.
  • Each group has N eligible faces (1, 1,000 or 10,000) plus one invisible and one deleted face. Another group has a visible face. All faces share one asset.
  • 3 warm-up rounds, then 12 measured rounds, alternating which version runs first. The page reports the median.
  • Timing covers the full method call, without the measuring plugin. A separate pass counts returned rows with a Kysely plugin and serializes them as JSON to estimate decoded size. That isn't wire bytes.

bcrypt

  • The original CryptoRepository.compareBcrypt (compareSync) is loaded from git. The patched one uses compare. Both run real bcrypt.
  • Each batch makes four checks of the password password against a cost-10 hash. Every batch must return four true results.
  • A setImmediate callback is queued before the batch starts. Its delay shows how long the event loop was blocked. The test asserts that 4 checks had finished when it ran for the original, and 0 for the patch, in every round.
  • 1 warm-up batch per version, then 6 rounds in alternating order. The page reports medians. No timing threshold is asserted.
  • Malformed hashes return false in both APIs. Bad argument types throw in the sync API and reject in the async one, and callers propagate the rejection.

Media requests

  • The original sendFile helper is loaded from git. The patched one is imported from source. Both call real Express sendFile over loopback HTTP using supertest, which opens a server per request.
  • 32 KiB temporary file on the local filesystem with the page cache not cleared. Range requests ask for 8 KiB. Concurrency 1.
  • 5 rounds per scenario in alternating order, each with 50 warm-up and 200 measured requests. The page reports the median time per 200 requests.
  • A spy around the real fs.promises.access counts calls.

Public smoke test

  • Authenticated curl over HTTPS through a Cloudflare Worker and tunnel to a temporary deployment of the patched server, with a separate database and uploads and machine learning off.
  • Rate limited to 128 KiB/s with --limit-rate 128k. One sample each for full download, conditional request and an 8 KiB range. Downloaded bytes were compared with the uploaded synthetic PNG.
  • This checks correctness only. The original server wasn't measured the same way. The deployment has been shut down.

What wasn't tested

  • The full Immich test suite. Only the focused suites listed in the server performance report ran.
  • End-to-end HTTP latency on low-end hardware, such as a NAS or single-board computer.
  • Added network latency, packet loss, outages or CPU throttling.
  • Memory use, or bandwidth between the server and clients.
  • Slow disks or network storage for the media change.
  • Many concurrent logins competing for the bcrypt worker pool.

Reading the numbers

Every benchmark ran on warm caches with synthetic data, on machines doing other work. Treat the face query and bcrypt results as large, consistent effects, and the media latency numbers as noise.

Reproduce

From server/ in a checkout with the patch applied:

RUN_BCRYPT_BENCHMARK=1 pnpm test run src/repositories/crypto.repository.benchmark.spec.ts
FILE_BENCHMARK_REF=256eb55dbe92ac77e02794442f9487e88ffed2b1 pnpm test run src/utils/file.spec.ts
RUN_PERSON_BENCHMARK=1 pnpm test:medium run test/medium/specs/repositories/person.repository.benchmark.spec.ts

The face query benchmark needs Docker for its PostgreSQL test container.
