Method and versions

The baseline is the method shipped in the official Immich v3.3.5 release, commit 8303cb117e197c700332b33b61b45314c9cc5bb4. The candidate method comes from OpenFrame commit 62a489eaf996267ec8c246412a2d13f6010d7b42 plus the exact patch and source hashes in the raw summary.

Both methods run on the same Linux box with an AMD A4-9125 CPU, inside the same pinned upstream server image with Node v24.22.1. Each process uses five warmup rounds and 30 measured rounds with alternating execution order. The repository is in memory. Each run includes 100, 1,000 and 10,000 checksums with 0%, 50% and 100% duplicates. Raw process files contain hardware, image digest, workload settings, individual samples and correctness checks.

Commands and the benchmark harness are in server/test/benchmarks. The preparation script takes an output directory and compiles the actual working-tree method. The run script verifies the upstream release and image before executing the prepared benchmark on the Linux box.

Limits and regressions

Not an end-to-end upload benchmark

This test excludes database queries, network transfer, storage writes, thumbnail generation and mobile clients. It cannot establish that OpenFrame as a whole is faster or has no regressions. Runs two and three overlapped dependency copying on the host. The observed process variation is not a confidence interval.

Correctness checks cover mixed hex and base64 encodings, repeated checksums, empty input, output order, duplicate rejection and trashed status. A baseline-versus-baseline control is retained in the repository. The separate HTTP deployment comparison is still in progress.
